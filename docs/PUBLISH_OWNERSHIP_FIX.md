# DEEPFORGE — исправление публикации при dubious ownership

Исправление касается только publish.bat. Код Stage 15, база данных и игровые
сохранения не меняются. В архиве нет .git, node_modules и сборок игры.

## Как применить

1. Замените publish.bat в существующей папке DEEPFORGE — рядом с package.json,
   папками client, server и существующей .git. Не создавайте новую папку проекта.
2. Запустите publish.bat обычным способом, не от администратора.
3. При сообщении `Trust this exact project folder and continue? [Y/N]:`
   проверьте путь и нажмите Y, только если это ваша доверенная папка проекта.
4. Скрипт добавит именно этот полный путь в пользовательскую настройку
   Git `safe.directory`, проверит доступ и продолжит обычную публикацию.

Можно передать сообщение коммита:

```bat
publish.bat "fix: repository ownership check before publish"
```

## Что исправлено

- Проверка доступа выполняется ДО локального git config и работы с origin.
- Только ошибка `dubious ownership` предлагает добавить исключение доверия.
- Исключение добавляется после подтверждения и только для одной папки.
- Нет `safe.directory=*`, смены владельца, изменения ACL или удаления .git.
- `DisableDelayedExpansion` сохраняет восклицательные знаки в путях, в том числе
  в папке `!!!GAMES`. Все пути заключены в двойные кавычки.
- Файл сохранён как ASCII без BOM, с окончаниями строк Windows CRLF.
- Ошибки настройки Git останавливают публикацию сразу, а не на следующем fetch.
- Отсутствие .git не приводит к созданию новой несовместимой истории.
- Публикация разрешена только из main; скрипт не переименовывает ветку.
- Добавлена проверка конфликтов после применения autostash.
- Имеющиеся настройки автора сохраняются; значения DEEPFORGE используются
  только если Git не находит имя или email.
- Успешный push не называется успешным деплоем: открывается GitHub Actions,
  где виден фактический результат сборки и публикации Pages.

Синхронизация использует обычный rebase с autostash, как раньше. При конфликтах
скрипт останавливается: он не выбирает версии файлов вместо пользователя.

## Область доверия

`safe.directory` — настройка доверия, а не исправление прав файловой системы.
Она позволяет Git работать с конкретным доверенным репозиторием, владелец
которого отличается от текущего пользователя. Другие чужие репозитории
по-прежнему не становятся доверенными благодаря этому патчу. Если ранее
пользователь сам включил wildcard, патч не меняет его существующие настройки.

Никаких токенов или паролей в файл добавлять не нужно.

## Проверки

В рабочей среде проверены ASCII/CRLF, метки и переходы bat-файла.
Отдельно на Git проверен сценарий: отказ при чужом владельце, разрешение
конкретного пути с Unicode и `!!!`, сохранение отказа для другой папки.

Нативного cmd.exe в этой среде нет. Полный запуск bat-файла на Windows,
доступ к GitHub с вашего компьютера и сборка Stage 15 здесь не проверялись.
