# DEEPFORGE — исправление Git и запуска тестов (16.1)

## Установка

Это патч инструментов, не новая версия игровой экономики.

1. Выберите ОДНУ папку с последними исходниками DEEPFORGE и UI/UX 16.1.
   На присланных скриншотах две разные папки: `LIFE TO LIVE` и `Шахтеры`.
   Название каталога не важно, но содержимое `package.json` должно принадлежать DEEPFORGE.
2. Скопируйте всё содержимое патча в эту папку, с заменой `publish.bat`
   и соответствующих файлов в `scripts`. Не переносите чужую `.git`.
3. Запустите `publish.bat`. Можно передать сообщение коммита:

```bat
publish.bat "fix: git recovery and TypeScript test launchers"
```

Батник напечатает текущую папку и версию проекта. Убедитесь, что это нужные исходники.

## Если Git сообщает о несовместимых историях

Программа сначала сохраняет локальные файлы, индекс, патчи и Git bundle в
`.git/deepforge-publish/backups/<id>` и создаёт локальную backup-ветку.

При неглубоком clone сначала запрашивается полная история. Это не изменение
исходников или перезапись коммитов.

Если общий предок по-прежнему отсутствует:

1. Программа покажет исходную папку и новый соседний каталог
   `DEEPFORGE-recovered-<дата>-<id>`.
2. На вопрос `Create a separate DEEPFORGE recovery copy?` ответьте Y,
   если напечатана правильная папка с вашей игрой. Будет создан свежий clone
   удалённой `main`, не объединение двух независимых историй.
3. Появится список файлов `ADD` / `REPLACE` и путь к полному плану переноса.
   Это перенос текущих локальных исходников поверх файлов нового clone.
   На вопрос `Apply these local DEEPFORGE files to the NEW folder, run all checks and push?`
   ответьте Y, если хотите публиковать именно эту версию игры.
4. Скрипт перенесёт только разрешённые файлы DEEPFORGE, затем запустит штатные
   `npm install`, `npm run typecheck`, `npm test`, `npm run build` и обычный push.
   Любая ошибка прерывает отправку.
5. В Windows откроется новая папка. В дальнейшем запускайте `publish.bat`
   и меняйте игру ИМЕННО В НЕЙ. Старую папку можно оставить резервной.

Старые исходники и `.git` не удаляются, не заменяются и не перенастраиваются
на новую историю. В исходной папке остаётся указатель на восстановленную копию;
повторный запуск из старого каталога остановится и напомнит нужный путь.

Если проверка в новом каталоге не прошла, исправляйте файлы и повторяйте запуск
в нём. Не создавайте новую восстановленную копию каждый раз.

Файлы, существующие только на GitHub, сохраняются. Отсутствие файла в локальной
независимой истории НЕ трактуется как просьба его удалить. Файлы локального
проекта с теми же путями заменяют версии только в новом clone после согласия.
Обычная синхронизация связанных историй по-прежнему проверяет merge в отдельной worktree.

`.git`, `node_modules`, сборки, архивы, `.env` и известные имена секретных файлов
не переносятся. `.env` и локальные служебные данные остаются в старом каталоге.
Если позже нужен локальный backend с индивидуальными настройками, перенесите
его приватный `.env` отдельно в новую папку; не добавляйте его в Git.
Проверка имён секретов не заменяет полноценный секрет-сканер содержимого.

## Ошибка TypeScript

Оба старых скрипта использовали закрытый subpath:

```js
require.resolve('typescript/bin/tsc')
```

Это было в `scripts/test-rift.mjs` и `scripts/test-ui-policy.cjs`.
Новый `scripts/local-typescript.cjs` читает установленный package.json с диска
и запускает CLI, указанный в публичном поле `bin.tsc`. Он не обращается к
недоступному package subpath, не использует глобальный tsc, npx или загрузку
новой версии компилятора. Поддерживается локальная установка в npm workspaces
и hoisted `node_modules`.

Node-launcher запускается через Node. Native-launcher распознаётся и вызывается
как исполняемый файл, а не JavaScript. Формат неподдерживаемого launcher даёт
ошибку; пути и аргументы не передаются через shell.

Компиляция изолированных проверок использует сгенерированный tsconfig и `--project`:
строгая проверка типов остаётся включённой, `noEmitOnError: true` блокирует
запуск тестов при ошибке компиляции. Существующие 19 проверок Rift и 10 проверок
UI-policy не отключены и не заменены заглушками.

## Что не изменено

- Игровые TS/TSX/CSS, механики и сохранения.
- Версии Node.js, TypeScript и других зависимостей в package.json.
- GitHub Actions workflow и GitHub-авторизация.
- Сохранённые коммиты удалённой `main`.

Ни `git clean`, ни hard reset, ни rebase, ни force-push, ни автоматическое
`--allow-unrelated-histories` не используются.

## Диагностика

Если публикация остановилась, читайте последнее сообщение и лог в РАБОЧЕЙ папке:

`.git/deepforge-publish/last-run.log`

В случае восстановления основной интерес представляет лог НОВОЙ папки.
Не отправляйте резервную копию `.git` целиком: в ней могут быть приватные данные.
