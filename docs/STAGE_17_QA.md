### Серверные сценарии

Открытие реактора только после завершения первого объекта; правила v1/v2; фиксированный отряд и блокировки объектов; точная валидация slot/target; запрет клиентских ядер/score/time; стоимость и пределы улучшений; личные cooldown; отсутствие сброса таймера при замене; запрет замены активного специалиста; идемпотентное начисление ядра; сохранность receipts Stage 16; отсутствующее прямое начисление score за навыки.

Проверены границы автоматического импульса 60/72 секунды, частичный/полный охват, минимум пропускных способностей, совпадение аналитического офлайна с частым чтением, совместное действие с навыками, окончание навыков внутри офлайна, лимит 4–7 часов, конец недели, покупка мощности в середине импульса, сохранение между объектами и отсутствие дохода после завершения.

Проверены параллельные повторы активации, rollback после отказа, новое создание RiftService поверх той же repository, разделение рейтинговых групп и естественный переход прежнего профиля в v2 в следующую неделю.

Полное прохождение v2 через обычные игровые команды без тестовой выдачи денег завершилось за **22,2 минуты симулированного серверного времени**, с 32 заработанными ядрами и 23 370 очками. Это конкретный тестовый сценарий, не обещание длительности прохождения для игрока и не окончательный коммерческий баланс.

### Разрешения макета

320×568, 360×640, 375×667, 375×812, 390×844, 393×852, 402×874, 414×896, 428×926, **430×932**, **430×774**, 440×956, 768×1024, 1024×768, 1366×768, 1920×1080.

Для портретных телефонов в проверках задаются тестовые верхний/нижний inset 59/34 px. Это проверка CSS с заданными отступами, а не физическая имитация Dynamic Island. Полный набор содержит текущие окна игры и 8 состояний реактора: закрыт, пустая команда, готовый специалист, активный импульс, cooldown, завершение, legacy, старый backend.

Снимки получены из **настоящего JSX и реальных серверных view** через статический renderer. Он не запускает React effects, Phaser, HTTP-запросы или события `onClick`. Native select синхронизируется с JSX value перед снимком. Проверки Dialog/viewport выполняются отдельно на настоящих DOM-элементах. Нельзя смешивать эти проверки с React E2E.

## Не проверено / требует следующего запуска

**Полные `npm run typecheck`, `npm test`, `npm run build` со всеми точными зависимостями проекта в этой среде не подтверждены.** Доступ к registry.npmjs.org отсутствует: curl возвращает code 6, `Could not resolve host`. Попытка npm install не завершилась и была остановлена лимитом времени. Реальное ядро компилировалось доступным TypeScript 5.8.3 через явные DF_TSC_PATH/DF_TYPE_ROOT; проект продолжает требовать прежние зависимости, включая TS 7.0.2. Версии не подменялись.

Не запускались физические iPhone/Safari, PWA-install, полностью работающий React/Phaser, живой VPS, реальная PostgreSQL и нагрузочный тест множества API-процессов. Поля JSONB/namespace аллокатора проверены кодом, но сетевой/PG runtime надо подтвердить на тестовом backend. Проверка повторного создания service на memory repository не является проверкой переживания перезапуска самого memory-процесса.

Исправленные publish.bat, Git helper, TypeScript helper и workflow **побайтово не менялись и не включены в обновление**. Нативный запуск BAT здесь не делался. Перед push обязательные проверки пользователя сохраняются и не заменяются имитацией.

## Проверка после применения

1. Распаковать обновление в действующую рабочую папку, запустить обычный publish.bat. Все проверки должны завершиться зелёным до push.
2. Обновить backend Stage 17 вместе с клиентом; PostgreSQL сохранять, старые данные не удалять. Проверить `apiVersion: 17` в /api/rift/status с авторизацией.
3. Новая попытка должна получить `rulesVersion: 2` и группу R2. Существующая v1 должна остаться прежней.
4. Дойти до объекта 2, назначить Rook, активировать навык: +1 ядро, активность 20 с, cooldown 60 с. Повторное нажатие/запрос не выдаёт второе ядро.
5. Получить 2 ядра, улучшить охват; получить ещё и открыть второй слот. Проверить доход и bottleneck во время импульса. Переключиться между вкладками и обновить страницу — состояние остаётся на сервере.
6. На iPhone 14 Pro Max проверить в Safari и PWA закрытие/скролл/выбор специалиста. Не очищать данные сайта. Без backend использовать явно обозначенный локальный DEV MEMORY, не выдавая его за онлайн-рейтинг.
