# Stage 16 — Rift Expedition

Версия проекта 0.16.0. Исходная версия: Stage 15, commit `7f6f2b31133d61857ba9ebd3ba89643fe78d5d59`.

## 1. Игровая модель

Отдельная экспедиция из пяти объектов. Недельный цикл начинается в понедельник в 00:00 UTC. Время, цены, баланс, право на награду и очки определяет сервер. На клиенте нет функции отправки произвольного score / cash / timestamp.

| Объект | Доход для завершения | Минимальный уровень всех звеньев |
|---|---:|---:|
| Врата разлома | 1 200 RC | 5 |
| Призматическая пещера | 5 000 RC | 8 |
| Кузница разлома | 22 000 RC | 12 |
| Обсидиановый узел | 90 000 RC | 16 |
| Хранилище ядра | 360 000 RC | 20 |

RC в этом режиме — **Rift Credits**, не кошелёк Rust Valley. Кошельки изолированы на уровне серверного состояния. Старт: 80 RC, 2 RP, добыча / лифт / логистика LV1. Все три звена работают автоматически. Деньги, друзья, Specialists, Equipment и глобальные множители обычных шахт в этот режим не импортируются.

Пропускная способность каждого звена: базовая скорость × коэффициент объекта × 1.16^(уровень−1) × профильная технология. Доход ограничен самым медленным звеном и множителем цены сырья. +1 и +10 рассчитываются геометрической суммой, оплачиваются полностью и атомарно; MAX уровня — 50.

Цель объекта использует **заработанный доход**, а не остаток кошелька: трата на улучшения не уменьшает прогресс цели. Переход требует также минимальные уровни всех трёх звеньев. Перед переходом UI запрашивает подтверждение.

При переходе сбрасываются локальные уровни, кредиты и доход объекта. Сохраняются RP, технологии экспедиции, очки и награды. Следующий объект получает стартовый бюджет с учётом своего масштаба. Завершённая экспедиция больше не производит доход, но позволяет забрать достигнутые награды.

## 2. Технологии

Шесть узлов, по три уровня. Цена последовательных уровней: 1 / 2 / 3 RP.

| Узел | Эффект за уровень | Предшественник |
|---|---|---|
| Резонансные буры | +12% добычи | Нет |
| Чистое сырьё | +8% цены ресурса | Буры LV1 |
| Силовые тросы | +15% лифта | Нет |
| Диспетчеризация | +15% логистики | Тросы LV1 |
| Бережливая сборка | −5% стоимости улучшений | Нет |
| Резервные склады | +1 час фонового накопления | Сборка LV1 |

RP выдаются за награды экспедиции: 2 за достижение половины цели и 4 за завершение объекта. RP и дерево не переносятся в следующую неделю. Respec внутри экспедиции не реализован.

## 3. Время, фон и награды

За промежуток без серверного checkpoint начисляется до 4 часов дохода; склад увеличивает предел до 7 часов. Накопление ограничено концом события. Визуальный таймер использует разницу serverNow + performance.now; клиентский Date.now не управляет экономикой.

10 milestones: 50% дохода и завершение каждого из 5 объектов. Награды включают материалы, Research Cores, ресурсы развития, Supply Keys и Rift Medals. RP доступны сразу для дерева. Остальные ресурсы сохраняются в отдельном серверном кошельке гостевого профиля и **пока не расходуются в обычной локальной игре**. Единый серверный инвентарь / безопасный перенос будет отдельной интеграцией.

Claim выполняется в одной транзакции с кошельком и состоянием полученных наград. При переходе на новую неделю сервер выдаёт достигнутые, но не забранные награды старой недели, записывает итог в историю и закрывает старый run. Начисление происходит при следующем обращении игрока; отдельный cron здесь не нужен. Хранится до восьми итогов, UI показывает последний.

## 4. Рейтинг

Группы до 100 реальных участников. Назначение группы атомарное. UI показывает первые десять мест и до двух соседей с каждой стороны своего места. Боты и выдуманные результаты не добавляются.

Очки: +10 × число купленных уровней × номер объекта; +1000 × номер объекта за завершение; однократный финальный бонус `floor(3000 / (1 + elapsedHours))`. Равенство: раньше достигнутый результат, затем ID с детерминированным порядком.

Итоговые медали: 1-е место — 30, 2–3-е — 20, 4–10-е — 10, остальные с ненулевым результатом — 5. Нулевой результат не получает рейтинговую награду. Лиг и повышения / понижения в Rift нет: это отдельная таблица от Blitz.

## 5. API и гостевой профиль

| Метод | Путь | Назначение |
|---|---|---|
| POST | /api/rift/guest | Выдать новый гостевой профиль и секретный ключ |
| GET | /api/rift/status | Состояние, серверное время, кошелёк и таблица |
| POST | /api/rift/start | Начать текущую экспедицию; повтор не сбрасывает run |
| POST | /api/rift/action | upgrade / research / complete / claim |

Гость получает RF-UUID и случайный секретный ключ длиной 32 байта. В БД хранится SHA-256 ключа, а не сам ключ. Авторизация: `Authorization: Bearer ...`. Player ID не является паролем. Ключ хранится браузером отдельно от основного save и отдельно для каждого адреса API. Очистка данных браузера может лишить доступа к этому гостю; привязки email / восстановления / облачной синхронизации ещё нет. Не публиковать ключ в логах, URL, скриншотах или Git.

Action содержит requestId, eventId, revision и только поля соответствующего действия. Лишние score, now, playerId, cash отвергаются, а не молча игнорируются. Повтор запроса с тем же UUID и содержимым не списывает ресурсы повторно. Повтор UUID с другим содержимым отвергается. Квитанции ограничены 128; старые запросы дополнительно блокируются revision и списком claimed.

UI не делает оптимистических покупок. При потерянном ответе перечитывает состояние и предлагает повторить тот же requestId. Запросы одного окна последовательны, статус опрашивается раз в 5 секунд только при открытом окне и видимой вкладке. Есть 8-секундный timeout и отмена статусных запросов при закрытии.

## 6. Сохранение и конкурентный доступ

Основной IndexedDB save остаётся schema v12; файлы миграции и хранения обычных шахт не изменены. Rift имеет отдельное серверное состояние rulesVersion=1.

При DATABASE_URL используется PostgreSQL: rift_accounts / rift_cohorts / rift_scores; схема `server/sql/003_rift.sql`, также инициализируется при запуске маршрутов. Обновления профиля защищены SELECT FOR UPDATE. Состояние, награда и score записываются одной транзакцией. Финализация недели получает exclusive advisory lock события и ждёт завершения действий под shared lock, чтобы не зафиксировать промежуточное место перед последним коммитом конкурента.

Без DATABASE_URL в development доступен MEMORY. Production без БД возвращает DATABASE_REQUIRED. Ошибка подключения к настроенной PostgreSQL не маскируется переключением на память.

HTTP limit ограничен процессом: 240 запросов / минуту на IP; 150 / минуту на ключ; 20 гостевых регистраций / час на IP. Для нескольких процессов и публичного запуска нужны ограничения reverse proxy, корректная политика IP и дальнейшая защита от массовой регистрации. Это не система предотвращения ботов или аудит безопасности всего приложения.

**Граница Stage 16:** старый Blitz Stage 15 использует прежнюю схему идентификации. Rift не переводит автоматически его endpoints на новую авторизацию. Перед публичной эксплуатацией всего соревновательного backend нужна отдельная миграция Blitz и проверка общего доступа / CORS / HTTPS / резервных копий.

## 7. Mobile portrait и нагрузка

Одна кнопка «События» вместо четырёх баннеров поверх шахты. Новое окно Rift: native dialog, четыре вкладки, собственный scroll, 100dvh, safe-area внутри панели только один раз, основные touch-зоны не меньше 44 CSS px. На телефоне блоки производства и технологии идут одной колонкой, сводка — 2×2. Переход на другую вкладку сбрасывает прокрутку её содержимого, а не всей страницы. На ПК окно ограничено 980 px и не растягивает элементы на весь монитор.

Rift не создаёт дополнительную Phaser-сцену. Под его непрозрачным окном пропускается обычное покадровое обновление визуального состояния шахты, а передача её данных в UI замедляется до одного раза в секунду. Экономика обычных шахт продолжает работать; весь Phaser-renderer не остановлен. После закрытия прежняя частота возвращается. Форматтеры чисел переиспользуются. В рейтинге клиент получает только TOP / соседей, а не весь список игроков.

## 8. Запуск и публикация

Локальный тест без БД: `dev_rift_memory.bat`, открыть http://localhost:5173. Скрипт не меняет .env и не сбрасывает файлы. MEMORY-профиль живёт только до перезапуска процесса.

Для PostgreSQL до запуска сервера задайте DATABASE_URL. CLIENT_ORIGIN для GitHub Pages — `https://divangames.github.io` (origin, без /DEEPFORGE/). HOST / PORT зависят от размещения; опубликованный API должен обслуживаться через HTTPS. Production задаётся через NODE_ENV=production. Сборка сервера: `npm run build -w server`; запуск: `npm run start -w server`.

Pages использует уже существующую GitHub Actions variable VITE_API_URL. Для Stage 16 нужно обновить серверный код отдельно. Ни ZIP, ни push клиента не устанавливают приложение на VPS.

`publish.bat` сохранён из исправленного рабочего main: ASCII / CRLF, DisableDelayedExpansion, точечное подтверждение safe.directory, без force-push. Pages workflow не изменён. Параметры зависимостей не менялись.
