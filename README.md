# DEEPFORGE — Stage 17: Reactor Grid

Дополнение к **Rift Expedition** на интерфейсе UI/UX 16.1. Приоритет — вертикальный телефон, затем планшет и ПК.

## Обновление существующего проекта

Этот архив содержит **только новые и изменённые файлы**. Распакуйте содержимое прямо в текущую рабочую папку DEEPFORGE, где находятся `.git` и уже исправленный `publish.bat`. Не создавайте новую `.git` и не переносите папки Git между проектами.

```bat
publish.bat "feat: stage 17 reactor grid"
```

Рабочий `publish.bat`, `scripts/deepforge-publish.cjs`, `scripts/local-typescript.cjs`, GitHub Actions workflow, `.env` и lockfile не заменяются. Зависимости не менялись; версии пакетов проекта стали `0.17.0`.

## Что добавлено

В **События → Rift Expedition → Реактор** реактор открывается на втором объекте. Он автоматически усиливает производство на 12 секунд каждые 60 секунд. За активации фиксированного отряда события выдаются ядра, которые расходуются на 1–3 слота, охват 1–3 звеньев и мощность ×2–×5. Личные cooldown сохраняются при замене специалиста. Все начисления выполняет сервер.

Начатые попытки Stage 16 не сбрасываются и доигрываются по прежним правилам. Новые попытки получают реактор и отдельные группы `R2-…`; следующая неделя автоматически переводит прежних игроков на новую систему. Основные сохранения шахт остаются schema v12.

## Сервер

Для сети нужно обновить **backend и frontend**. Push/Pages не обновляет API на VPS. В production нужна PostgreSQL; схема таблиц прежняя, данные реактора сохраняются в JSONB. Без backend онлайн-режим не имитируется.

Локальная проверка без БД: `dev_rift_memory.bat` → `http://localhost:5173` → новая экспедиция. После закрытия memory-сервера её профиль и рейтинг исчезнут; обычные локальные шахты сохранятся.
